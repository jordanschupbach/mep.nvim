*mep.txt*   A zero-dependency, modular collection of Neovim Lua libraries

==============================================================================
mep.nvim                                                                 *mep*

A zero-dependency Neovim plugin/distribution using a modular architecture
of a collection of independent Lua libraries under one repo. No
`plenary`, no `telescope`, no external Lua deps — only Neovim's built-in
APIs plus, where a library chooses to shell out, standard CLI tools
(currently: `rg`, optionally `git` + a C compiler for |mep-treesitter|'s
parser installer, and `curl` for |mep-ai|'s own LLM streaming — only
needed if you actually use that library).

Each library lives at `lua/mep/<name>/` with an aggregator entry file of
the same name that aggregates the pieces implemented in sibling files —
e.g. `lua/mep/core/core.lua` aggregates `coroutines.lua`, `job.lua`,
`parallel.lua`, `util.lua`. A thin `init.lua` shim in each directory just
does `return require('mep.<name>.<name>')`, so both
`require('mep.<name>')` and `require('mep.<name>.<name>')` work. Nothing
has a side effect just from being `require`d — behavior only happens once
a library's `setup()` is called (or, for |mep-picker|, when one of its
picker functions is invoked directly).

                                      Type |gO| to see the table of contents.

REQUIREMENTS                                                *mep-requirements*

- Neovim >= 0.9 (|mep-lsp| specifically needs >= 0.11 — `vim.lsp.config`/
  `vim.lsp.enable` — and warns and no-ops on anything older rather than
  erroring).
- `rg` (ripgrep) on `PATH` for `:MepLiveGrep`. `:MepFindFiles` uses `rg`
  too when present (faster, respects `.gitignore`) and otherwise falls
  back to a synchronous directory walk.
- `git` and a C compiler (`cc`/`gcc`/`clang`) on `PATH` for
  |mep-treesitter|'s parser installer. Not required for treesitter
  "activation", which only uses parsers already available.
- `curl` on `PATH` for |mep-ai|'s LLM streaming, only if you use it.

SETUP                                                              *mep-setup*

`require('mep').setup(opts)` is optional — every library works with its
own defaults if you never call it — but it's how you configure more than
one library at once: `opts.<name>` is forwarded to `mep.<name>.setup()`.
>lua
    require('mep').setup({
      theme = { default = 'nord' },
      sanity = { leader = ' ' },
      dashboard = { auto_open = true },
      icons = { style = 'nerd_font' },
      filetree = { width = 30 },
      treesitter = { fold = true },
      org = { todo_keywords = { 'TODO', 'DOING', 'DONE' } },
      markdown = { tables = true, code_blocks = true },
      picker = { debounce_ms = { dynamic = 150 } },
      whichkey = { triggers = { '<leader>' } },
      sidebar = { position = 'right' },
      notify = { position = 'top-right' },
      activitybar = { position = 'right' },
      lsp = { enable = true },
      completion = { sources = { 'lsp', 'buffer', 'path' } },
      url = { keymaps = { open = { 'gx' } } },
      git = { sidebar = { position = 'left' } },
      window = { manual = { resize_step = 5 } },
      project = { readme_names = { 'readme.txt' } },
      scratch = { filetype = 'markdown' },
    })
<
Equivalent to calling `require('mep.sanity').setup({ leader = ' ' })`,
`require('mep.icons').setup({ style = 'nerd_font' })`, and so on
yourself — use whichever fits how you organize your config. Omit a
library's key (or the whole call) to just get its defaults.

Libraries are applied in a fixed order (`sanity` before `theme`/
`whichkey`, since both bind `<leader>`-based keymaps that need
`mapleader` already set; `sidebar` before `notify`/`activitybar`, since
those build `mep.sidebar` instances) — see `lua/mep/init.lua`'s own
`CONFIGURABLE_LIBRARIES` list and its header comment for the exact
reasoning per library.

Global modifier keys                                       *mep-modifier-keys*

Default keymaps across mep are written with a `<Mod1-...>` placeholder
instead of hard-coding `<A-...>`: `Mod1` resolves to Alt (`'A'`) on
Linux/Windows and Option (`'M'`, i.e. Option-as-Meta) on macOS, and every
library's `setup()` expands the placeholder (via `mep.core.keys`) in
both its defaults and any keymaps you pass in, so you can use
`<Mod1-...>` in your own overrides too.
>lua
    require('mep').setup({
      -- Use Cmd instead of Option for every Mod1 binding (macOS GUIs
      -- like Neovide; terminals generally can't send Cmd):
      mods = { mod1 = 'D' },
    })
<
Additional names (`mod2`, `mod3`, ...) have no built-in default but
expand the same way once configured (e.g. `mods = { mod2 = 'C' }` makes
`<Mod2-x>` mean `<C-x>`).

Note for macOS terminal users: for Option to reach Neovim as Alt/Meta at
all, the terminal must be set to send it that way — iTerm2's "Option
key: Esc+", kitty's `macos_option_as_alt`, Neovide's
`macos_option_key_is_meta`. That's a terminal setting, not something a
plugin can do for you.

==============================================================================
mep.core                                                            *mep-core*

Async/parallel building blocks with no `setup()` of their own — plain
libraries used directly.

- `mep.core.coroutines` — minimal async/await on native Lua coroutines
  (`wrap`, `await`, `run`, `async`). Turn any callback-style API into
  something you can write as straight-line code.
- `mep.core.job` — async external-process runner on top of
  `vim.fn.jobstart`, streaming stdout/stderr line-by-line.
- `mep.core.parallel` — genuine parallelism via libuv's threadpool
  (`vim.uv.new_work`): `parallel.map(items, work_fn, on_done)` runs
  `work_fn` on worker OS threads. `work_fn` runs in an isolated Lua
  state, so it can't close over locals or call `vim.*` — only pure
  computation on its arguments.
- `mep.core.util` — `debounce`, `find_root` (nearest ancestor with
  `.git`), `scan_dir` (synchronous recursive file listing fallback).

mep.sanity                                                        *mep-sanity*

A small, growing set of opinionated-but-overridable Neovim defaults, each
independently configurable and individually disableable (set its option
to `false`):

- **leader** (`leader`) — sets `mapleader`/`maplocalleader`. Default
  `' '` (space).
- **tabs** (`tabs`) — tab keymaps. Default `<C-t>` (`:tabnew`),
  `<Mod1-1>`..`<Mod1-9>` (jump straight to tab 1-9) — not
  `<C-Tab>`/`<C-S-Tab>`-style cycling, since most terminals don't send a
  distinguishable code for those at all.
- **number**/**signcolumn** (`gutter`) — turns on line numbers and the
  sign column (always shown, not just `'auto'`). Both default to `true`.

>lua
    require('mep.sanity').setup({})
    -- leader = ' ', tabs.keymaps = { new = {'<C-t>'}, select = {'<Mod1-1>',...,'<Mod1-9>'} },
    -- number = true, signcolumn = true
    require('mep.sanity').setup({ leader = ',' })
    require('mep.sanity').setup({ leader = false }) -- don't touch mapleader at all
    require('mep.sanity').setup({ tabs = { keymaps = false } }) -- no tab keymaps
<

mep.theme                                                          *mep-theme*

28 built-in colorschemes (19 dark, 9 light: `gruvbox-dark`/`-light`,
`nord`/`-light`, `dracula`, `tokyo-night`, `catppuccin-mocha`/`-latte`,
`one-dark`/`-light`, `everforest-dark`/`-light`, `rose-pine`/`-dawn`,
`solarized-dark`/`-light`, `monokai`, `kanagawa`, `ayu-dark`/`-mirage`,
`github-dark`/`-light`, `nightfox`, `horizon`, `zenburn`, `synthwave84`,
`oxocarbon-dark`/`-light`). Each theme is a compact ~13-field palette
(bg/fg plus seven accent hues) rendered by one shared, data-driven
generator covering every standard Neovim highlight group plus common
treesitter `@`-captures.

>lua
    require('mep.theme').setup({}) -- default='gruvbox-dark', apply_on_setup=true, keymaps.picker={'<leader>ut'}
    require('mep.theme').apply('nord')
    require('mep.theme').list() -- every registered theme name, sorted
    require('mep.theme').register('my-theme', {
      dark = true, bg = '#000000', fg = '#ffffff', red = '#ff5555',
      green = '#50fa7b', yellow = '#f1fa8c', blue = '#8be9fd',
      purple = '#bd93f9', cyan = '#8be9fd', orange = '#ffb86c', border = '#44475a',
    })
<
`<leader>ut` (or `:MepThemePicker`) opens a fuzzy picker over every
registered theme: moving the selection applies it live and renders a
color-swatch breakdown in the picker's preview sidebar; Enter commits,
Escape/`<C-c>` reverts to whatever was active before. `:MepTheme {name}`
(tab-completes) applies one directly.

Commands ~
    :MepTheme {name}         Apply a theme directly (tab-completes).
    :MepThemePicker          Open the fuzzy theme picker.

mep's own custom highlight groups all `link` to standard groups this
renders, so they track whichever theme is active automatically.

mep.dashboard                                                  *mep-dashboard*

Takes over the initial empty buffer at startup — the same trigger
conditions as Neovim's own `:intro` screen (no file arguments, a single
untouched empty buffer, one window, no piped stdin) — and renders
content into it instead: a constructed recreation of Neovim's own intro
message by default, with a block-character logo above `NVIM vX.Y.Z` and
an `MEP vX.Y.Z` line under it (both computed live).

>lua
    require('mep.dashboard').setup({}) -- auto_open = true, content = 'intro'
    require('mep.dashboard').setup({ content = { 'Welcome!', '', ':MepFindFiles to start' } })
    require('mep.dashboard').setup({ content = function() return {...} end })
    require('mep.dashboard').setup({ auto_open = false })
<
Commands ~
    :MepDashboard             Show the dashboard in the current window.
                               Lua: require('mep.dashboard').open()

Content is centered both horizontally and vertically; the window's own
gutter (`number`/`relativenumber`/`signcolumn`) is turned off for as
long as that window keeps showing the dashboard.

Highlight groups ~
    MepDashboardLogo          block-character logo (links to Title)
    MepDashboardVersion       NVIM/MEP version lines (links to Title)
    MepDashboardCommand       `:command<Enter>` hints (links to Special)
    MepDashboardLink          URLs (links to Underlined)

mep.icons                                                          *mep-icons*

Looks up an icon glyph for a file (by exact basename, then lowercased
extension, falling back to a generic file icon) or a directory
(closed/open variants), plus a matching tree-expand marker. Three
styles:

- `nerd_font` (default) — monochrome Nerd Font glyphs with real
  per-language differentiation, pulled from nvim-web-devicons' own
  default-icon tables.
- `emoji` — standard Unicode emoji covering ~40 common extensions and a
  few special filenames. Renders everywhere, no font needed.
- `ascii` — plain 7-bit fallback, no per-type icons.

>lua
    require('mep.icons').setup({ style = 'emoji' })
    require('mep.icons').get_file_icon('main.lua')      --> icon, 'MepIconFile'
    require('mep.icons').get_directory_icon(true)        --> open-folder icon, 'MepIconDirectory'
<
Layer your own icons on top of (or instead of) the built-ins per style
via `overrides`, e.g.
`overrides = { emoji = { by_extension = { lua = '🌛' } } }` — see
`lua/mep/icons/data.lua` for the full built-in tables.

mep.filetree                                                    *mep-filetree*

A single persistent tree panel (a real vertical split, not a floating
window) backed by lazy, one-level-at-a-time directory scanning. Always
renders through |mep-icons| — its icon style (and any `overrides`) come
from `require('mep.icons').setup({...})`.

Commands ~
    :MepFileTreeToggle        Open/close the tree.
                               Lua: require('mep.filetree').toggle()
    :MepFileTreeRefresh       Re-scan expanded directories in place.
                               Lua: require('mep.filetree').refresh()

`toggle()`/`open()` accept an optional `{ root = ... }`, defaulting to
`mep.filetree.config.options.root` and then `core.util.find_root()`.

Keymaps (inside the tree, normal mode) ~
    <CR> / o           Open file under cursor (in the window the tree
                        was opened from), or toggle a directory
    <C-o>              Open with the OS's default program (`vim.ui.open`)
    l / <Right>        Expand directory under cursor
    h / <Left>         Collapse an expanded directory, or jump to parent
    q / <Esc>          Close the tree
    R                  Refresh
    a                  Create a file/directory (trailing `/` = directory)
    r                  Rename the file/directory under the cursor
    d                  Delete the file/directory under cursor (confirms;
                        directories removed recursively)
    ?                  Toggle a popup listing every keymap above

>lua
    require('mep.filetree').setup({
      width = 30, root = nil, show_hidden = false,
    })
<
All configurable: `width`, `root`, `show_hidden`, and
`keymaps.open`/`open_system`/`expand`/`collapse`/`close`/`refresh`/`add`/
`rename`/`delete`/`help` (each a list of lhs strings) — see
`lua/mep/filetree/config.lua` for the full defaults.

Highlight groups ~
    MepIconFile               file icons (links to Normal)
    MepIconDirectory           directory icons (links to Directory)
    MepFiletreeDirectory       directory names in the tree (links to Directory)

mep.treesitter                                                *mep-treesitter*

Two separate things, both on by default:

- **Activation** (`mep.treesitter.activate`) — starts highlighting
  (`vim.treesitter.start`), and optionally folding, for any buffer whose
  filetype has a parser available from anywhere (bundled with Neovim,
  installed by mep, or installed by anything else). Pure `vim.treesitter`
  API, no network, no compiler.
- **Installing** (`mep.treesitter.install`) — a curated registry of
  ~40 common languages (including `org` for |mep-org|). Missing parsers
  are fetched (`git clone --depth 1`) and compiled (`cc`/`gcc`/`clang`)
  in the background on `setup()`, installed to
  `stdpath('data')/site/parser/`. Degrades gracefully (one warning,
  nothing installed) if git or a compiler isn't found. Each install also
  copies that grammar's own upstream `queries/` directory to
  `stdpath('data')/site/queries/<lang>/`.

>lua
    require('mep.treesitter').setup({}) -- highlight=true, fold=false, ensure_installed=true
    require('mep.treesitter').setup({ ensure_installed = { 'lua', 'python', 'rust' } })
    require('mep.treesitter').setup({ ensure_installed = false }) -- activate-only
    require('mep.treesitter').setup({ fold = true })
<
Commands ~
    :MepTreesitterInstall {name}    Install one parser (tab-completes
                                     the curated list).
    :MepTreesitterInstallAll        Install every parser in the curated
                                     registry.

mep.org                                                              *mep-org*

Org-mode structure, editing, and highlighting, built in phases — see
`ORGMODE_ROADMAP.md` for what's shipped vs. not yet. What's landed:
headline structure/editing, TODO state, priorities, dates/scheduling,
tags (inheritance, match syntax, fast selection, alignment), links
(parse/conceal/follow/insert/store), plain lists, sparse-tree search,
property drawers, clocking/effort, capture templates, an agenda
(day/week/global-TODO/tag-search across `agenda_files`), org-babel
(execute/tangle `#+begin_src` blocks, poly-mode LSP/highlighting per
block), org-export (ascii/markdown/html), footnotes, generic blocks,
macros, `#+INCLUDE:`, org-id, attachments, checkboxes/statistics
cookies, folding/visibility, sorting, narrowing, archiving, refiling,
and easy templates.

Everything except highlighting is pure line-pattern parsing (no
tree-sitter parser required), so structure editing works even before
the `org` parser is installed. Key modules: `mep.org.outline` (headline
navigation/promote/demote/move), `mep.org.edit` (insert headlines),
`mep.org.todo` (cycle TODO state), `mep.org.priority` (`[#A]` cookie
cycling), `mep.org.timestamp` (active/inactive dates, repeaters),
`mep.org.plan` (SCHEDULED/DEADLINE), `mep.org.tags` (inheritance, fast
selection, alignment), `mep.org.tagmatch` (filter-expression parsing),
`mep.org.link`/`mep.org.linkconceal`, `mep.org.checkbox`/`statistics`,
`mep.org.sort`/`narrow`/`archive`/`refile`/`visibility`/`templates`,
`mep.org.list` (bulleted/ordered items), `mep.org.sparse` (sparse-tree
search), `mep.org.property` (`:PROPERTIES:` drawers), `mep.org.clock`
(clocking, clocktable report), `mep.org.capture` (templates, `<C-c>c`),
`mep.org.agenda` (`<C-c>a`), `mep.org.babel` (`<C-c>e`/`<C-c>E`; ~25
languages resolved to whatever interpreter/compiler is on PATH),
`mep.org.fold`, `mep.org.block`, `mep.org.footnote`, `mep.org.macro`,
`mep.org.include`, `mep.org.id`, `mep.org.attach`, and `mep.org.export`
(`<C-c><C-e>`, ascii/markdown/html backends; real org tables aren't
part of the model, LaTeX/PDF/ODT are out of scope).

Poly mode (`mep.org.polyglot`, active by default) gives each
`#+begin_src <lang>` block real syntax highlighting (tree-sitter
injection) and real LSP features (hover/definition/references/
rename/diagnostics/completion) sourced from that language's own server,
via a hidden "shadow buffer" per language kept in sync at the same line
numbers. `polyglot = false` turns off the LSP bridging (highlighting is
unaffected); `polyglot = { keymaps = {...} }` rebinds just its keymaps.

>lua
    require('mep.org').setup({})
    -- todo_keywords={'TODO','DONE'}, todo_highlight=true,
    -- todo_keyword_colors={TODO='DiagnosticError', DONE='DiagnosticOk'},
    -- highlight=true, fold=true, sort_criteria='alpha', priorities={'A','B','C'},
    -- tags={}, tags_column=77, conceal_links=true, capture_templates={},
    -- agenda_files={}, deadline_warning_days=14, attach_dir='data',
    -- polyglot={keymaps={...}}
    require('mep.org').setup({
      todo_keywords = { 'TODO', 'DOING', 'WAITING', 'DONE', 'CANCELLED' },
      todo_keyword_colors = { TODO = 'DiagnosticError', DONE = 'DiagnosticOk' },
    })
    require('mep.org').setup({ capture_templates = {
      { key = 't', description = 'Task', target = { file = '~/todo.org' }, template = '* TODO %? %a' },
    } })
    require('mep.org').setup({ agenda_files = { '~/notes/*.org' }, deadline_warning_days = 7 })
    require('mep.org').setup({ polyglot = false })
<
Keymaps (inside org buffers) ~
    <C-c><C-n> / <C-c><C-p>        Next / previous headline
    <Mod1-Left>/<Mod1-Right>       Promote/demote current headline
    <Mod1-S-Left>/<Mod1-S-Right>   Promote/demote whole subtree
    <Mod1-S-Up>/<Mod1-S-Down>      Move subtree among siblings
    <Mod1-CR> / <Mod1-S-CR>        Insert sibling headline / TODO headline
    <C-c><C-t>                     Cycle TODO state
    <C-c>,                         Cycle priority cookie
    <C-c><C-c>                     Toggle checkbox under cursor
    <Tab> / <S-Tab>                Toggle fold / cycle global visibility
    <C-c>^                         Sort current headline's siblings
    <C-c>n / <C-c>N                Narrow / widen to current subtree
    <C-c><C-x><C-a>                Archive current subtree
    <C-c><C-w>                     Refile current subtree (via mep.picker)
    <C-c>. / <C-c>!                Insert/edit active/inactive timestamp
    <C-c><C-s> / <C-c><C-d>        Schedule / set deadline
    <C-a> / <C-x>                  Adjust timestamp under cursor by
                                    [count] days
    <C-c><C-q>                     Fast tag-selection popup
    <C-c><C-o>                     Follow link under cursor
    <C-c><C-l>                     Insert link (normal, visual)
    <C-c>l                         Store link to current headline
    <C-c>> / <C-c><                Indent / outdent list item
    <C-c>#                         Renumber ordered list at cursor
    <C-c>/                         Sparse-tree search
    <C-c><C-x>p                    Set a property
    <C-c><C-x><C-i>/<C-x><C-o>     Clock in / clock out
    <C-c><C-x><C-r>                Insert/refresh clock-table report
    <C-c>c                         Capture (normal, visual)
    <C-c>a                         Agenda
    <C-c>e / <C-c>E                Execute src block / tangle buffer
    <C-c><C-x>f                    Footnote action
    <C-c><C-x>i                    Get-or-create :ID: property
    <C-c><C-a>                     Attach a file to current headline
    <C-c><C-e>                     Export (ascii/markdown/html)

    <CR>                           Continue list item (insert mode)
    gd/gD/gr/gi/<leader>lt          Poly mode: LSP goto-* (in a src block)
    K / <C-k>                      Poly mode: hover / signature help
    <leader>rn                     Poly mode: rename

Fixed (non-configurable) inside the capture popup: `<C-c><C-c>` files
the entry and closes, `<C-c><C-k>` aborts. All other keymaps are
configurable via `require('mep.org').setup({ keymaps = {...} })` — see
`lua/mep/org/config.lua` for the full defaults.

mep.markdown                                                    *mep-markdown*

Distinct highlighting for markdown structure, layered on top of
|mep-treesitter|'s install+activate pipeline, plus a sign-column marker
per heading line, box-drawn GFM tables, and shaded fenced-code-block
backgrounds.

- **Headers** — `@markup.heading.1`..`.6` each linked to a distinct
  group so nesting depth is visible at a glance.
- **Emphasis** — bold/italic colored on top of your theme's own weight.
- **Gutter** (`mep.markdown.gutter`) — one sign per ATX heading line,
  a circled digit by default (`①`-`⑥`, `config.gutter_symbols`).
- **Tables** (`mep.markdown.tables`) — re-renders GFM pipe tables as
  real box-drawn tables via overlay extmarks; the row under the cursor
  is left un-overlaid so you can edit it directly.
- **Code blocks** (`mep.markdown.codeblocks`) — shades every line of a
  fenced code block with `MepMarkdownCodeBlock`.

>lua
    require('mep.markdown').setup({})
    -- highlight=true, headers=true, emphasis=true, gutter=true,
    -- gutter_symbols={'①',...,'⑥'}, tables=true, code_blocks=true
<
No dedicated toggle command — like |mep-org|, it activates automatically
via `FileType`.

mep.picker                                                        *mep-picker*

A `Picker` (`lua/mep/picker/engine.lua`) drives a floating-window layout
— prompt on top, results below, preview sidebar on the right — with
fuzzy matching (a dependency-free fzf-style subsequence scorer) and live
preview of the selected item.

Commands ~
    :MepFindFiles              Project files (`rg --files`, or a pure-
                                Lua walk if `rg` isn't installed).
                                Lua: require('mep.picker').find_files()
    :MepLiveGrep                File contents across the project, via
                                `rg` (required).
                                Lua: require('mep.picker').live_grep()
    :MepBufferSearch            Lines of the current buffer.
                                Lua: require('mep.picker').buffer_search()
    :MepBuffers                 Open (listed, loaded) buffers, MRU first.
                                Lua: require('mep.picker').buffers()
    :MepCommands                 User-defined Ex commands.

mep.completion                                                *mep-completion*

mep.ai                                                                *mep-ai*

gptel-style LLM streaming and a tool-calling agent, in any buffer.
`:MepAiSend` (`gl` in normal mode) sends the whole current buffer's text
to a configured LLM and streams the response in at the cursor.
`:MepAiCancel` (`<leader>ax`) stops an in-flight request early.

`gl`/`gk` in **visual** mode open a persistent side-panel, interactive,
multi-turn, tool-calling agent (`mep.ai.agent`) scoped to the selection.
`gk` first prompts for an explicit instruction. `mep.ai.send_selection()`
(`:MepAiSendSelection`/`:MepAiSendSelectionPrompt`) is an older,
single-shot, no-tools version that replaces the selection directly.

>lua
    require('mep.ai').setup({}) -- provider={'openai','anthropic','ollama'}, keymaps: send/agent={'gl'}, agent_prompt={'gk'}, cancel={'<leader>ax'}
    require('mep.ai').setup({ provider = 'anthropic' })
    require('mep.ai').setup({ provider = { 'anthropic', 'ollama' } })
    require('mep.ai').setup({ system_prompt = 'Answer tersely.' })
    require('mep.ai').setup({ tools = { 'read_file', 'list_dir' } }) -- drop run_command
<
Three named `providers` presets: `openai` (Chat Completions API,
`OPENAI_API_KEY`, `model='gpt-4o-mini'`), `anthropic` (Messages API,
`ANTHROPIC_API_KEY`, `max_tokens=4096`, `model='claude-sonnet-5'`), and
`ollama` (local `ollama serve`, no key, `model='llama3.2'`). `provider`
can be a single name (prompts for its key) or a list tried in order with
no prompting — the default list lands on `ollama` if neither API key is
set, so `gl` works with zero `setup()` calls once `ollama serve` is
running.

Commands ~
    :MepAiSend                          Send buffer to the LLM, stream at cursor.
    :MepAiCancel                        Cancel an in-flight request/agent turn.
    :MepAiSendSelection                 Replace a range with the LLM's response (range).
    :MepAiSendSelectionPrompt            Same, prompts for extra instructions first (range).
    :MepAiAgent                          Start the tool-calling agent panel (range).
    :MepAiAgentPrompt                    Same, prompts for extra instructions first (range).
    :MepAiSetKey [provider]              Prompt for and cache an API key.

Tool-calling agent (visual-mode gl/gk) ~
Three tools ship by default (`config.tools`): `read_file`/`list_dir`
(`risk = 'read'`), `run_command` (`risk = 'exec'`, `sh -c`). Every tool
call is a permission prompt in the panel: `a` allows once, `d` denies,
`A` grants a standing "always allow" approval — but only for `risk =
'read'` tools; `run_command` always asks. `i` types a free-text reply.
There is deliberately no dedicated "edit the buffer" tool — edits happen
via a real shell command against the file on disk, picked back up by
Neovim's own `:checktime` semantics. Tool-calling requests are
non-streaming.

- `mep.dap.breakpoints` — session-only, keyed by absolute file path.
  `toggle(bufnr, lnum)`/`list(bufnr)`/`clear(bufnr)`/`clear_all()`;
  sign-column gutter (`MepDapBreakpoint`).
- `mep.dap.session` — one active session at a time: `launch(adapter_name,
  args)`/`attach(...)` run the full DAP handshake;
  `launch_interactive()` prompts for both. `continue`/`step_over`/
  `step_into`/`step_out`/`terminate`/`evaluate(expression, callback)`
  control it; `subscribe(fn)` hears every change.
- `mep.dap.sidebar` — a `mep.sidebar`-built panel (call stack / scopes
  / variables / breakpoints).
- `mep.dap.repl` — a persistent console buffer for `output` events;
  `evaluate_interactive()` prompts for an expression.

>lua
    require('mep.dap').setup({}) -- keymaps.toggle_breakpoint=<leader>db, continue=<leader>dc, ...
    require('mep.dap').setup({ adapters = { debugpy = { cmd = { 'python', '-m', 'debugpy.adapter' } } } })
    require('mep.dap').session.launch('debugpy', { program = '/path/to/script.py' })
<
Commands ~
    :MepDapToggleBreakpoint       Toggle a breakpoint on the current line.
    :MepDapLaunch                  Start a session (prompts for adapter + program).
    :MepDapContinue                 Continue the active session.
    :MepDapTerminate                 Terminate the active session.
    :MepDapSidebar                    Toggle the debug sidebar.
    :MepDapRepl                        Toggle the debug console.

Highlight groups ~
    MepDapBreakpoint         breakpoint gutter sign (links to DiagnosticError)
    MepDapStopped              current-line sign where paused (links to DiagnosticWarn)
    MepDapReplTitle              debug console's winbar title (links to Title)

mep.docs                                                            *mep-docs*

Docstring generation and external doc lookup.

- `mep.docs.generate` (`<leader>ld`) — inserts a language-appropriate
  doc-comment skeleton for the function on the cursor line. Tries a
  real `textDocument/signatureHelp` request first when a capable client
  is attached; falls back to a single-line regex scan otherwise.
  Curated for python/lua/go/rust/ruby/javascript/typescript(react)/c/
  cpp/java.
- `mep.docs.lookup` (`<leader>lD`) — opens external documentation for
  the word under the cursor via `mep.url.open`: a devdocs.io
  instant-search deep link, biased toward the right doc set via a
  per-filetype hint when curated.

>lua
    require('mep.docs').setup({}) -- keymaps.generate=<leader>ld, lookup=<leader>lD
    require('mep.docs').setup({ doc_hints = { python = 'python~3.13' } })
<
Commands ~
    :MepDocsGenerate       Insert a docstring skeleton for the current function.
    :MepDocsLookup          Open external docs for the word under cursor.

mep.flashcards                                                *mep-flashcards*

Spaced-repetition review, org-drill style, over org headlines tagged
`config.options.tag` (`:drill:` by default, inheritance-aware) collected
across `config.options.drill_files` (the same literal-path/glob-pattern
shape |mep-org|'s own `agenda_files` uses).

- **Scheduling** (`mep.flashcards.sm2`) — the classic SM-2 algorithm, a
  4-button grade vocabulary (again/hard/good/easy) mapped onto SM-2's
  0-5 quality scale. State lives in the headline's own `:PROPERTIES:`
  drawer.
- **Review UI** (`:MepFlashcardsReview` /
  `require('mep.flashcards').review_session()`, default `<leader>fr`) —
  one card at a time in a floating popup: headline title as the
  question, `<CR>`/`<Space>` reveals the body as the answer, then
  `a`/`h`/`g`/`e` grades it and advances. A no-op (with a notification)
  when nothing's due.

>lua
    require('mep.flashcards').setup({ drill_files = { '~/notes/*.org' } })
    require('mep.flashcards').setup({ tag = 'flashcard' }) -- use :flashcard: instead of :drill:
<
>org
    * Capital of France? :drill:
    Paris.
<
Commands ~
    :MepFlashcardsReview      Start a spaced-repetition review session.
